# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

Expo SDK 57 / React Native（react-native-web 网页演示）+ 本地 Node 后端（server/，端口 8787）。比赛演示走网页版（localhost:8081）。

## Users

比赛评委（星火计划超级个体 OPC 挑战赛，几分钟看完 demo）和普通用户（想吃得健康、想开始运动但不知从哪下手的人，尤其学生/久坐办公族）。

## Product Purpose

一款"吃 + 动"双入口健康助手。两大特色：① 拍照识别手头食物 → AI 生成食谱（营养环图/热量对比/换做法）；② 身体数据 → 按身体数据推送匹配的运动视频（信息流）。用一次拍照/一次填表解决"吃什么"和"怎么练"。

## Positioning

"拍一下食材，告诉你该怎么吃；填一下身体数据，告诉你该怎么练。" 大模型图像理解 + 生成能力，把两个最难坚持的场景变成一次操作。AI 不可替代性 = 图像识别（看懂真实食物）+ 个性化生成（因人而异的食谱与运动方案）。

## Operating Context

- 软件赛道比赛 demo，评委几分钟看完；两条可独立演示的闭环（拍照→食谱 / 填表→视频）。
- 集训 2026-08-19，现场须可跑通（后端 + 网页 App 都要起）。
- AI 接入：真 API（OpenAI 兼容）可随时开，未配置时自动用内置演示数据（已标注）。

## Capabilities and Constraints

- 已实现：5 Tab 导航（首页/社区/菜谱/练/我的）、账号注册登录与游客模式、身体数据/健身目标、拍照识别食材（相机/相册/手动修正/历史）、AI 菜谱生成（条件/营养环图/热量对比/收藏/换做法）、健身短视频推荐（信息流/分类/详情/外部视频跳转）、个人中心+数据看板。
- 明确砍掉/未做：社交评论、头像上传、站内托管的真实版权视频内容。视频流当前按本地视频库和目标规则筛选，AI 实时排序待后续恢复。
- 技术约束：真实 AI 模式下，照片 Base64 经本地后端转发至火山方舟进行识别，不在本地长期保存；页面标注"非医疗用途"与运动安全免责；演示数据明确标注。

## Brand Commitments

无绑定承诺。产品名暂用 "Shanghai Project"（正式名待定）。

## Evidence on Hand

- 无真实用户、无数据。演示素材（食谱、运动视频库）自造，已标注演示数据。
- 不得虚构商用数字、用户量或减肥效果承诺。

## Product Principles

1. 三十秒讲清：这是什么、AI 替用户做了什么、价值在哪。
2. 两条功能各有一条完整可演示闭环，各自独立跑通。
3. 演示优先于完整产品：核心闭环跑通 > 边角打磨。
4. 不编造医疗效果、用户量等事实；演示数据明确标注。

## Accessibility & Inclusion

未建立产品级要求。基础可访问性（对比度、键盘可达、减弱动效）作为默认标准执行。
